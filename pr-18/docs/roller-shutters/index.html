Written steps and troubleshooting

Step-by-step instructions

Follow the interactive example above or use the written steps below. Waveshare drives the motor through two relays; Hearth reports wall-button gestures; Home Assistant connects them into shutter control.

Before you start

  • Install OSELIA Hearth and Waveshare Modbus RTU Relay, then restart Home Assistant.
  • Add your relay board using Serial or Network (TCP). Each board on a shared bus needs a unique Modbus address.
  • For wall-button control, connect Hearth to MQTT and verify its input event entities are available. You can create and test the shutter without a wall button.
  • Sign in as an administrator to access OSELIA Config.
  • Motor installation should already be complete. Identify two different unused relay channels on the same board, one for opening and one for closing.

1. Pair the relays

  1. Open Settings → Devices & Services.
  2. On Waveshare Modbus RTU Relay, choose Configure → Add a roller shutter.
  3. Fill in the form:
FieldValue
NameA useful name, such as Living room shutter
Relay boardThe board connected to this motor
Up relay (opens)Your opening relay number
Down relay (closes)Your closing relay number
Up travel time (seconds)Leave at 0 initially
Down travel time (seconds)Leave at 0 initially
  1. Choose Submit. A new cover entity appears on the board’s device.

Numbers match the Relay 1, Relay 2, … labels. Channels 1 and 2 in the demonstration are examples: use your actual wiring. Both directions need different channels, and a channel cannot belong to another shutter.

2. Test movement

Open the new shutter on the board’s device page. Check Open → Stop → Close → Stop through the cover entity, which coordinates the two directions.

If the directions are reversed, stop movement and use Configure → Edit a roller shutter to correct the Up / Down relay numbers. Editing preserves the entity, history and bindings.

3. Enable position control (optional)

Open / Close / Stop already work with zero travel times.

  1. Measure a complete opening run, starting fully closed.
  2. Separately measure a complete closing run, starting fully open.
  3. Enter both times in seconds under Configure → Edit a roller shutter, then save.
  4. Complete a full run to an end position to synchronize the estimate.

The position slider is available when both travel times are greater than 0. 0% means closed; 100% means open. Position is estimated from motor running time, not measured by a position sensor. The demonstration’s 24 and 26 seconds are examples only.

4. Put the shutter in its room

  1. Open Settings → Devices & Services → Entities, select the cover, then ⚙.
  2. Turn off Use device area.
  3. Select the actual Area, such as Living room, and choose Update.

Keep the board device in the utility room; the cover gets its own room. Create missing rooms under Settings → Areas, labels & zones. The automation’s area and the button input’s area do not determine where the shutter tile appears.

5. Bind the wall button

  1. Open OSELIA Config in the sidebar.
  2. Enable Listen for presses, then hold the physical wall button.
  3. Choose Use in form ↓ in the detected-input banner.
  4. Check Input (wall-switch) and Gesture → Long press.
  5. Set Target (light / cover) to your shutter cover and Action to open.
  6. Set a Name, such as “Living room — open shutter”, then Save binding.
  7. Repeat for the second button with action close. You can also create a separate stop binding.

Each binding creates an ordinary Home Assistant automation. Repeating the same configured gesture while the shutter is moving stops it by default. Single press can remain bound to a light. Double press requires enabling it in the firmware; this example only needs long press.

6. Check the resident dashboard

Reload your existing resident dashboard. To create one:

  1. Settings → Dashboards → Add dashboard → New dashboard from scratch → name it OSELIA → Create.
  2. Open it → ⋮ → Edit dashboard → ⋮ → Raw configuration editor.
  3. Replace the contents with:
strategy:
  type: custom:oselia-resident
  1. Choose Save. The shutter appears under its entity’s room.

Only entities bound to wall buttons appear on the resident dashboard. Check control from both the tile and the physical button.

Troubleshooting

SymptomCheck
No board to selectAdd one via Configure → Add a relay board first.
Relay channels rejectedUse distinct channels within the board’s channel count, not assigned to another shutter.
No position sliderEnter both full travel times, greater than 0.
Button not detectedCheck Hearth availability, MQTT and Listen for presses.
No shutter tileSave a binding targeting that cover in OSELIA Config, check Automation health and reload the dashboard.
Tile in the utility roomDisable Use device area on the cover entity and assign its Area.
